03

工具系统：把自然语言变成动作

项目的可展示亮点：LLM 只选工具，工具返回统一结构。

工具像一排专业仪器

Agent 手里不是一把万能锤，而是一组命名清晰的 工具。每个工具只做一类业务动作。

01

data_filter

统一旱天筛选入口，后续分析的地基。

02

analyze_rainfall

日降雨、场次划分、降雨图表。

03

assess_risk

旱天和雨天运行风险评估。

04

generate_report

把已计算结果装配成 DOCX 报告。

真实注册：data_filter 是一个 Agent 工具

装饰器 `@agent.tool` 把普通 Python 函数暴露给 Agent。

CODE 
@agent.tool
def data_filter(
    ctx: RunContext[AgentDeps],
    missing_rate_threshold: float = 0.1,
    expected_rows_per_day: int = 1440,
    rain_day_filter_threshold: float = 2.0,
    zero_like_threshold: float = 0.02,
    high_zero_ratio_threshold: float = 0.5,
    high_zero_ratio_normal_days_threshold: int = 5,
PLAIN ENGLISH

把 data_filter 注册成 Agent 可调用工具。

ctx 里带着路径、日志、session 等依赖。

默认参数就是业务规则的默认阈值。

用户明确要求时，Agent 才会覆盖这些参数。

这让工具既稳定，又能被自然语言配置。

工具返回协议

statusok / needs_input / error，告诉 Agent 下一步该继续还是追问。
summary给用户看的业务摘要，要包含关键数字和异常提醒。
artifacts本次生成的 Excel、PNG、DOCX 文件路径。
data结构化数据，供报告生成或后续工具复用。
