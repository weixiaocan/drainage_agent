02

架构分层：谁负责什么

这一页帮你把“项目很散”讲成“职责清晰的分层系统”。

像一栋楼：每层只管自己的事

这个项目的关键不是用了多少库，而是分层边界清楚。面试里可以先画这棵 架构图。

app/CLI 和 Web 启动入口
web/FastAPI 页面、聊天、上传、下载
agent/Pydantic AI Agent、工具注册、依赖、会话状态
analysis/领域算法：降雨、RDII、风险、排污规律、报告
resources/演示数据和 DOCX 模板
quality/pytest 测试和评测脚本

03

工具系统：把自然语言变成动作

项目的可展示亮点：LLM 只选工具，工具返回统一结构。

工具像一排专业仪器

Agent 手里不是一把万能锤，而是一组命名清晰的 工具。每个工具只做一类业务动作。

01

data_filter

统一旱天筛选入口，后续分析的地基。

02

analyze_rainfall

日降雨、场次划分、降雨图表。

03

assess_risk

旱天和雨天运行风险评估。

04

generate_report

把已计算结果装配成 DOCX 报告。

真实注册：data_filter 是一个 Agent 工具

装饰器 `@agent.tool` 把普通 Python 函数暴露给 Agent。

CODE 
@agent.tool
def data_filter(
    ctx: RunContext[AgentDeps],
    missing_rate_threshold: float = 0.1,
    expected_rows_per_day: int = 1440,
    rain_day_filter_threshold: float = 2.0,
    zero_like_threshold: float = 0.02,
    high_zero_ratio_threshold: float = 0.5,
    high_zero_ratio_normal_days_threshold: int = 5,
PLAIN ENGLISH

把 data_filter 注册成 Agent 可调用工具。

ctx 里带着路径、日志、session 等依赖。

默认参数就是业务规则的默认阈值。

用户明确要求时，Agent 才会覆盖这些参数。

这让工具既稳定，又能被自然语言配置。

工具返回协议

statusok / needs_input / error，告诉 Agent 下一步该继续还是追问。
summary给用户看的业务摘要，要包含关键数字和异常提醒。
artifacts本次生成的 Excel、PNG、DOCX 文件路径。
data结构化数据，供报告生成或后续工具复用。

用户要求雨天风险，但没有指定降雨场次，工具最合适的返回是什么？

这一模块回答面试官最可能追问的问题：你怎么保证分析结果可信？

降雨场次划分、旱天筛选、RDII、风险评估都在 Python 函数里明确计算。面试时要强调：确定性计算 是这类工程应用的底线。

你可以讲的工程取舍

1
schema 是唯一事实源

避免每个工具各自猜列名，减少隐性不一致。

2
原始数据和筛选数据分离

`load_flow` 读原始数据，`load_filtered_flow` 读 data_filter 标准产物。

3
LLM 只补充解释

排污规律文字可以借助模型，但 Kz、峰谷比、风险值来自算法。

如果某个点位流量分析结果明显异常，最合理的第一步是？

06

工程质量：能上线也能解释

最后用这一页收束：这个项目有测试、日志、缓存、容器化和边界控制。

可追溯：每次结果都有指纹

fingerprint 和 manifest 让系统知道结果是否还可信。这是数据分析 Agent 很重要的工程能力。

CODE 
def record_result(deps: AgentDeps, tool_name: str, artifacts: list[str], params: dict[str, Any] | None = None) -> None:
    manifest = load_manifest(deps)
    manifest.setdefault("version", 1)
    manifest.setdefault("results", {})
    manifest["results"][tool_name] = {
        "generated_at": datetime.now().isoformat(timespec="seconds"),
        "data_fingerprint": data_fingerprint(deps)["digest"],
        "params": params or {},
        "artifacts": artifacts,
    }
PLAIN ENGLISH

每个工具跑完后，都更新 manifest。

记录生成时间，方便追踪。

记录输入数据指纹，判断结果是否过期。

记录参数，区分不同范围或阈值的结果。

记录产物路径，让 Web 可以列出和下载。
