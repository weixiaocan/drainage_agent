# 保留 Pydantic AI，并在项目感知的对话运行模块后使用

Agent 继续使用 Pydantic AI 处理模型调用、类型化工具和消息协议；应用在其外建立项目感知的对话运行模块，从 SQLite 装载项目事实并持久化会话、约束、确认状态和运行关联。项目事实不得从聊天历史推断，Pydantic AI 也不拥有项目事实。

没有采用 LangGraph，因为当前确定性工作流、分析运行和后台作业已经由领域模块及 SQLite 持久化；再引入图检查点会形成第二套状态与恢复语义。没有完全自研 Agent 循环，因为现有 Pydantic AI 工具、模型适配、历史处理和 Eval 已得到验证，重写不能为 Ticket 11–12 增加相称的能力。

对话运行模块是 Web、CLI 与 Agent 之间的 seam。若未来出现多个跨进程的长时间暂停节点、补偿流程或复杂并行编排，再以独立 ADR 重新评估图运行时。
