# 公开演示环境

项目需要一个可公开访问的 Demo，用于作品展示和部署验证。Demo 部署在维护者自有的服务器和域名下，使用与自部署相同的 Docker Compose 和核心应用，通过 `DRAINAGE_DEMO_MODE=1` 进入受限模式；不提供 SaaS 或多账户服务。

演示的目标是让访客体验全部分析能力，因此只限制会破坏共享数据或产生不可控费用的部分：没有账户体系时所有访客共用同一份数据，数据操作必须禁止；模型调用按次数限额。

## Consequences

- 演示模式拒绝上传或替换数据、创建项目、删除、重置工作区、上传模板，以及下载原始数据和全部文件；关闭 FastAPI 接口文档。
- 对话接口按访问 IP 限制每分钟请求数（`DRAINAGE_DEMO_REQUESTS_PER_MINUTE`，默认 3）、同时进行的对话数（`DRAINAGE_DEMO_MAX_CONCURRENT_CHATS`，默认 2），以及每人每天（`DRAINAGE_DEMO_DAILY_CHATS_PER_VISITOR`，默认 20）和全站每天（`DRAINAGE_DEMO_DAILY_CHATS_TOTAL`，默认 300）的提问次数。每日计数按北京时间切换，保存在内存中，应用重启后清零。
- `run_python` 在演示中可用，与自部署版本使用同一套策略：只读统计自动执行，需要额外能力（如保存文件）时请访客审批，危险操作直接拒绝。访客审批的是自己的请求，因此审批不构成安全边界；安全依靠代码策略检查和一次性沙箱（无网络、只读输入、资源与时间上限）。
- 只能使用脱敏演示数据。服务器地址、密钥和部署凭据不写入仓库。
- 目前由维护者按 `docs/DEPLOY_DEMO.md` 手动部署。主分支自动部署、失败回滚和定时恢复演示数据尚未实现。
