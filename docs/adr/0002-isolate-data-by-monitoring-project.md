# 一个部署实例支持多个相互隔离的监测项目

排水监测分析人员通常同时负责多个项目，为每个项目单独部署一套 Docker 实例既浪费资源也不便于管理。因此，一个部署实例必须允许创建和切换多个监测项目，并按项目隔离输入数据、分析基线、结果、报告和对话记录；第一版不提供多人协作或多租户能力。

## Consequences

项目身份必须贯穿 Web 请求、Agent 会话、文件路径、结果清单和新鲜度判断。现有共享 `resources/data`、`var/outputs`、`var/workspace` 与全局依赖状态的设计不能作为多项目版本的数据边界。

每个监测项目可以包含多个相互独立的分析批次。上传新数据时创建新批次，不自动合并、去重或覆盖旧批次；跨批次分析必须由工程师明确发起，并创建保留来源信息的派生分析批次。

创建派生分析批次时，如果来源批次在相同点位和时间上存在重复或数值冲突，系统必须停止合并并展示冲突范围和数量，由工程师选择保留的来源；不得静默去重或默认采用最新上传的数据。
